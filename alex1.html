Architecture
Core Systems
ALEX-1 is built around four architecture-defining subsystems, each documented through formal ADRs.
ADR-011 · Architecture-Defining

Three-Layer Memory

Working memory handles active conversation context. Episodic memory stores interaction histories with timestamps and emotional context—including user corrections that feed the self-learning loop. Semantic memory accumulates long-term knowledge about user preferences, routines, and device relationships. Together they enable ALEX-1 to learn across sessions instead of resetting every conversation.

ADR-012 · Architecture-Defining

Multi-Modal Emotion

Facial analysis via MediaPipe + DeepFace, voice emotion from pitch/energy/MFCC extraction via Librosa, and text sentiment analysis through transformer models. Three signals fused for 89.7% accuracy. The assistant adapts communication style to your mood—more empathetic when you're frustrated, more energetic when you're engaged.

ADR-002 · Architecture-Defining

Home Assistant Layer

Built on Home Assistant for instant 2,000+ device support across Zigbee 3.0, WiFi, and Matter/Thread. The most important architectural decision in the project: device control is a commodity—ALEX-1's differentiation is the AI intelligence layer, not writing Zigbee drivers. Communication via WebSocket API and Wyoming Protocol.

ADR-018 · Architecture-Defining

Edge-First Privacy

All personal data processing happens locally. Voice biometrics stored as irreversible embedding templates, never raw audio. Emotion data never leaves the device. Cloud features are optional subscription add-ons, never required. This eliminates GDPR Article 9 special category obligations and drops compliance costs from $600K–$1.1M to $2K–$5K annually.

Voice Pipeline
From Wake Word to Spoken Response
End-to-End Pipeline

openWakeWord (ADR-006) detects the wake phrase → faster-whisper base.en (ADR-004) transcribes speech at ~0.3s for 5-second utterances → Hierarchical intent classifier (ADR-019) at 94.2% accuracy, <200ms latency → llama.cpp (ADR-003) running gemma3:1b at Q4_K_M quantization for response generation → Piper TTS (ADR-005) converts response to natural speech. Total pipeline: 2–3 seconds on Raspberry Pi 5, competitive with cloud-dependent Alexa at 1.5–2.5s.

Decision Log
Key Architecture Decisions
20 formal ADRs document every technical choice. Here are the most impactful.
ADR-001

Raspberry Pi 5 8GB

BCM2712 SoC with ARMv8.2-A native dot-product and FP16 support. gemma3:1b at Q4_K_M runs at ~12 TPS. Complete BOM at 1,000 units: ~$137 for ~31% gross margin at $199 retail. Natural upgrade path: Pi 5 → CM5 carrier → custom PCB at scale.

ADR-003

llama.cpp for LLM

Raw llama.cpp in server mode over Ollama. 10–20% faster on Pi 5—that overhead matters at the edge of usable latency. GGUF format support, server mode for API access, and >10 TPS on 1B models.

ADR-007

Zigbee-First Protocol

Zigbee 3.0 as primary protocol via Zigbee2MQTT + Mosquitto (ADR-008). Mesh networking for whole-home coverage, no cloud dependency, and the broadest range of affordable smart home devices.

ADR-009

NVMe SSD Mandatory

Critical reliability decision: no microSD for production. SD cards have 3–6 month expected lifetime under Home Assistant's continuous database writes. NVMe SSD is a hard requirement for any deployment.

ADR-013

Hailo-10H Deferred

AI accelerator HAT deferred to Phase 2. The 1B model runs adequately on CPU. Adding hardware acceleration before proving the software architecture would be premature optimization. Reserved for when 3B+ models are needed.

ADR-015

Resemblyzer for Speaker ID

Voice embedding for speaker identification—ALEX-1 knows who is speaking and personalizes responses per family member. Embeddings are irreversible templates that can't reconstruct the original voice, preserving privacy.

Development Infrastructure
Hybrid Cloud-Edge Development
ADR-001 (Infrastructure) · Accepted

Development happens on an Oracle Cloud VM (clawdbot: 4 OCPU, 24GB RAM) running the full stack—Home Assistant, MQTT, LLM server, voice pipeline. Edge deployment to Pi 5 comes after software validation. This approach was born from necessity (Pi 4 SD card corruption) and became the architecture: cloud for heavy development, edge for production deployment.

ADR-002 (Operations) · Accepted

ALEX-1 operates as a Telegram bot via OpenClaw on the Oracle Cloud instance, powered by Claude Opus 4.6. The "mind/body" framing: the Telegram bot is ALEX-1's mind (conversational intelligence, memory, decision-making). The codebase is ALEX-1's body (smart home product). The mind helps build the body—starting the adaptive learning loop months before hardware ships.

Strategic Position
Where ALEX-1 Fits

2030 Consumer Product

ALEX-1 is strategically positioned as a 2028–2030 consumer product. Current development builds critical IP and infrastructure while the market matures. 67% abandonment rate of current voice assistants after 6 months signals the opportunity for one that actually learns.

Cross-Pollination

MediaPipe pipeline and edge architecture from EMOTE4D transfer directly. Multivac's model routing logic and category classification inform intelligent query routing—code questions to code-optimized models, communication to writing-optimized models. Three projects compound on each other.

What We're NOT Building

Explicitly deferred: Z-Wave support, full Matter certification ($27K–$35K), custom PCB ($500K+ NRE), mobile app, cloud LLM fallback, multi-language support. Focus creates speed—everything not in the critical path is removed until the moment it's needed.
